## 用户授权后的安装方式

甲方索引提供原生 `vllm[audio]==0.32.0+flagos` 及 repack 包，普通源补充 regex、pytest 等。新 Dockerfile 使用 uv 的 unsafe-first-match 策略，甲方源有兼容版本时优先，无兼容版本才补普通源（甲方 setuptools 只有 70.2.0、84.2.1，缺少所需 80.10.2）；普通源默认 Aliyun，可通过 INDEX_URL 调整。

`docker/cuda/constraints.txt` 固定 Runtime 的核心包（含 CUDA 13 NCCL），防止安装音频 extras 时自动升级 NumPy。实验首次无约束安装确曾升级 NumPy；随后按约束恢复至 1.26.4，后续镜像直接使用约束。setuptools 调整为 80.10.2；ModelScope 与仓库 pyproject 对齐为 1.35.3。

补充包和精确版本见 `docker/cuda/requirements-ci.txt`。包括 pytest 及 xdist/cov/timeout/json-report、构建工具、decorator、ModelScope、音频包、XGBoost/scikit-learn。FFmpeg 通过 apt 安装。FlagGems-vllm 使用仓库共享安装器固定 v0.2.0 Git commit `b5c2c2249319277ccda4d41aa0f65164bd9b2a19`（包元数据仍为 0.1.0）。

Standalone Triton 3.7.1 用于满足 Torch 分发元数据；实际导入编译器保持 Runtime `/opt/flagtree` 的 Triton 3.6.0。检查器核对实际模块路径，不能通过 Python `-I` 清掉 Runtime 的 PYTHONPATH。

## E2E 发现的工具链问题与处理

首次 27B eager 用例未通过，原因依次验证如下（不是 regex 缺失）：

1. FlashInfer JIT 默认调用 `/usr/local/cuda/bin/nvcc`，此 Runtime 不包含这个文件；闭包中的 nvcc 实际在 `/flagos/lib/python3.12/site-packages/nvidia/cu13/bin/nvcc`。设置 CUDA_HOME、CUDA_PATH 和 PATH。
2. 未约束闭包选到了 nvcc/CRT/NVVM 13.5.37，但 Torch 的 cuda_runtime.h 为 CUDA 13.0，CCCL 报编译器与头文件不兼容。约束三项均为 13.0.88，保留 Runtime Torch 的 CUDA 13.0 runtime/header。此处是闭包新增的编译工具版本调整，不是替换 Runtime 的 Torch 或 CUDA 驱动。
3. 编译通过后链接报 `cannot find -lcudart`。Runtime 只有 libcudart.so.13，pip toolkit 使用 lib 而不是 lib64。新增 lib64→lib、libcudart.so→libcudart.so.13 两个链接，不复制/替换实际动态库。
4. 独立调用 `flashinfer.comm.trtllm_mnnvl_ar.get_trtllm_mnnvl_comm_module()` 已成功编译、链接并加载，`JIT_LINK_EXIT=0`。完整模型用例随后重新执行。

已把上述约束、工具链环境和链接写入 Dockerfile；失败日志按 e2e-final-matrix.log、e2e-toolchain-matrix.log、e2e-aligned-matrix.log 保留，最终重试为 e2e-ready-matrix.log。

## 可反馈甲方的闭包改进项

- 普通源补齐 regex 等包；甲方单索引还缺所需 setuptools 80.10.2，不能只把所有包名放在索引就认为版本闭包完整。
- XGBoost 引入的 nvidia-nccl-cu12 与 Runtime nvidia-nccl-cu13 共享文件路径。镜像暂通过最后恢复 cu13 原库避免覆盖；建议甲方提供不引入 CUDA 12 NCCL 的 XGBoost 方案或统一依赖，否则后续重新安装 cu12 包可能再次破坏 Torch。
- 新增 CUDA 编译工具必须与实际头文件匹配。本次用 nvcc/CRT/NVVM 13.0.88，不能无约束选 13.5；还需给 pip toolkit 配置 CUDA_HOME/PATH、lib64 和 libcudart 链接。
- 库文件可加载、pip check 成功、UT 成功，均不能代替完整模型 E2E；本次问题确实是在首次大模型请求触发 FlashInfer JIT 时才出现。
