# PR455 integration review, September 20, 2026

This revision follows the shared review of PR455 `4e800f7` and PR544
`2d68733`. Performance acceptance uses the installed PR455 + PR544 + PR442
integration wheel. PR442 subsequently merged into main `71f6148`; both public
branches now inherit it through main. After conflict resolution, all 283
packaged model runtime files (excluding generated version metadata) match the
measured integration wheel exactly. No private benchmark branch is pushed.

## Implementation

- PR544 owns metadata policy (`stock`/`eager`/`graph`), generation lifetime and
  `PreparedMetadata`. PR455's packed arena supplies storage and transfers;
  it no longer selects another metadata policy or graph owner. PR442 supplies
  the fused multi-group producer under that owner. Its final head `3035692`
  differs from the tested `4e3540a` only in CI/Docker files. Pointer tables
  expire with the InputBatch generation.
- The producer clears each group's logical block-table width. Packed views
  can have a larger row stride containing neighboring groups. The former
  stride-sized clear could overwrite those groups or allocation guards.
  A shared-storage capture/replay regression covers active and padded rows.
- `flaggems_runtime` owns global registration, immutable configuration and
  failed initialization. Shape-aware MM retains its handles and selector.
  Disabled or excluded MM does not parse the threshold. Successful observed
  `lib=` registration establishes the callable; repr and package source paths
  are diagnostic. The registration-stack adapter is limited to Torch 2.11.
  The model's exclusions, native sorting and plan-cache bridge remain active.
- Optional native completion is isolated in draft
  [PR547](https://github.com/flagos-ai/vllm-plugin-FL/pull/547). This model and
  the performance runs use accelerator Events. The draft has no new native
  extension, real CUDA-context fault or serving-performance acceptance.
- KV bind preflights all owners and the ABI before mutation. Binding failure
  aborts initialization and requires discarding the runner; recursive rollback
  of arbitrary layer containers has been removed.
- Behavior tests replace source/AST assertions. QSA workspace validation enters
  actual `_warmup_and_capture`; PLE request replacement, resume, finish and
  abort/resubmit enter actual `_update_states`. Loader transaction and
  independent QSA reference tests remain. The `context * 7` replay case is
  explicitly a fixed-address consumer smoke test.
- Merging current vendor support exposed a stale platform alias in MoE apply.
  The execution entry now resolves the active platform before vendor selection;
  NVIDIA and Kunlunxin dispatch regressions cover the merged branch.

Both final profiles use the installed integration wheel plus the same
immutable FlagGems dependency snapshot with the reduction fix below. They run
on one 8x H100 80GB node with image
`sha256:b7faa60041af787c35de236685120fb072697a6547fa4ef5877095f7f1519d87`,
Torch 2.11.0+cu129, vLLM 0.24.0, TP8, async scheduling, 64 server slots,
16384 batch tokens, memory utilization 0.85, no prefix caching, no custom

ranks. Requested FULL resolves to FULL_DECODE_ONLY. The 1024/1024 profile

### Required FlagGems reduction fix

The first 4K candidate completed 384 marker requests, but repeated greedy
generation differed at token 17. Full-model traces of four cases on all eight
ranks first diverged at the first MoE output despite identical MoE inputs,
before the first QSA layer. Isolated BF16 tests at the actual TP8 geometry
(512 experts, hidden 2560, intermediate 80, top-k 10) reproduced differences
in all eight repeats at 4096 tokens. Keeping GEMM tuning but using the existing
fixed-order FP32 `moe_sum` made all repeats exact.

[FlagGems #6492](https://github.com/flagos-ai/FlagGems/pull/6492), commit
`e341d3cc95c5c15150622a38b8b151ab59311096`, restricts direct atomic accumulation
to top-k = 1. Multi-expert calls keep per-expert outputs and a fixed-order FP32
reduction, while retaining the large-token GEMM tile tuning. Twelve CUDA
regressions pass across BF16/FP16 and 1024/4095/4096/4097 tokens, including
Graph reuse with changing inputs and independent grouped PyTorch references.
The repeated-output regression fails against the unpatched parent.

Serving uses the pinned `5.3.3.dev15+gf471641e5.pkgfix1` source snapshot with
**only** `flag_gems/fused/fused_moe.py` changed. It does not upgrade the other
2582 dependency files to upstream master. The package version still describes
the base; the complete 2583-file SHA256 manifest and patch provenance identify
the measured dependency. Startup verifies every dependency file and every
installed plugin file before launching the worker.

The [module patch](flaggems_deterministic_moe.patch) applies to the pinned
FlagGems source root with `git apply`. Its original module SHA256 is
`a780da6348ba611640b546b47c60b79baa1312094386ce8f49d99d0d8e4750af`;
the required patched SHA256 is
`2f8d8cda969a206c7f3e80a3f5dfa5f3dc9d28b048bd96edba457108cac29acc`.
The benchmark startup gate now checks this module as well as the entry and
plan-cache modules. Apply the patch to a separate dependency copy before
starting a service; do not modify a running service's dependency tree.

The earlier 1K candidate measured 3365.91 tokens/s and passed its checks;
the earlier 4K candidate measured 2370.68 tokens/s but failed serial reuse.
Both are superseded by the final patched-stack measurements above. Failed
serial responses, per-layer traces, operator A/B results, cold/unstable groups
and client/startup failures are preserved. The initial independent operator
reference was corrected to match the existing plain-half GEMM1 rounding;
that failed attempt is also retained.

The final patched 1K run needed two complete repeats: the first two groups
had 21.56% and 17.90% drift, with maximum token intervals of 4.106 and 3.417
seconds. Those intervals overlap 20 and 6 new cubin writes respectively,
including MoE alignment and QSA metadata kernels. The selected group has no
token interval over one second. These are warmed-serving measurements;
compilation-related startup/shape pauses remain visible in the retained data.
Cache-write correlation is evidence of concurrent compilation, not a complete
CPU-time attribution of each pause.

Cold pauses in the earlier 1K group overlap Triton cache writes: 35 cubin
writes during a 3.25-second token pause and 304 during an 8.95-second pause,
including MoE and QSA variants. This supports compilation as a contributor,
without attributing every historical pause or promising cold-start latency.

Hardware and serving samples are recorded in `review2_validation.json`:
temperature, clocks, throttle flags, KV usage, running/waiting requests and
preemptions for the selected formal intervals. Sampling cannot exclude events
between samples. The previous-stack reference has hardware samples but no
Prometheus series.

## Scope

The model worker resolves requested FULL to FULL_DECODE_ONLY. Mixed FULL
remains experimental and emits a warning after global graph policy resolution;
FULL_DECODE_ONLY decode is not mistaken for mixed FULL. The common probe
cannot label mixed FULL accepted.

These short-context serving checks do not certify 100K context, long reasoning,
GPQA accuracy, arbitrary batch invariance or non-H100 accelerator execution.
PIECEWISE's fixed maximum request extent remains a correctness-oriented
baseline; its cost at large request/context/group capacities is not measured
by these short-context experiments.
